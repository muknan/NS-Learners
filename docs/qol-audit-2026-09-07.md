# QOL audit and improvements — 7 September 2026

Reviewed the application routes, shared controls and styling, exam state and timing,
scoring and result identity, storage and recovery, flashcards, navigation guards,
offline configuration, content schemas, build configuration and existing tests.
Started as a read-only audit; implementation followed the user's subsequent instruction.

## Findings addressed

| Priority | Finding                                                                                  | Resulting behavior                                                                                                                                            |
| -------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | The exam error boundary deleted saved answers on render.                                 | Errors preserve the attempt and offer Retry; results errors also offer Retry.                                                                                 |
| High     | Starting a retake silently overwrote an inactive saved retake.                           | A dialog offers resume, cancel or explicit replacement. The existing mode lock still protects an open retake.                                                 |
| High     | Jumping to question 25 could lock road rules without showing the section explanation.    | Every manual section crossing, including keyboard and auto-advance, goes through confirmation before locking answers.                                         |
| High     | Resuming long after the first deadline granted a new 30-minute section.                  | The second deadline follows the first deadline when resuming late. Attempts resumed after both deadlines are submitted as expired.                            |
| Medium   | Result pages depended on a shared latest-result slot.                                    | Submission opens the completed attempt by its history ID, so another result cannot change the page on reload. History retention remains ten attempts.         |
| Medium   | Different exam modes could write history concurrently.                                   | Result writes share a Web Lock around the existing storage operation.                                                                                         |
| Medium   | An open tab could restore an attempt cleared elsewhere.                                  | The affected exam stops and explains that its attempt was cleared in another tab.                                                                             |
| Medium   | Save and reset failures were silent or transient.                                        | Result saving has a persistent retry action; home resets and flashcard saves display errors; error notifications remain until dismissed.                      |
| Medium   | Flashcard updates used stale known-card sets.                                            | Changes read the latest saved set and other tabs synchronize their visible known cards. Exact simultaneous cross-tab writes are not made transactional.       |
| Medium   | Flagged answers did not trigger a submission review.                                     | Submission warns about flagged and unanswered counts.                                                                                                         |
| Medium   | Result breakdowns repeated the same categories, and “missed” meant two different things. | Categories appear once; skipped answers are called “Unanswered”; the review badge counts questions to review. Perfect topics no longer appear as weak topics. |
| Medium   | The longer score label overflowed at 320px.                                              | Narrow score strips use a compact grid with labels below their values.                                                                                        |
| Medium   | Two-action dialogs wrapped into an uneven stack.                                         | Actions occupy equal-width columns and can wrap text within each button.                                                                                      |
| Medium   | Compact exam settings duplicated IDs and left focus behind.                              | Controls have unique IDs, opening moves focus inside, Escape/Close restores it, and tabbing away closes the popover.                                          |
| Low      | Resume could disappear despite another saved mode.                                       | The header falls back to other active attempts. The full-exam result action distinguishes Resume from Start.                                                  |
| Low      | The save-and-exit query was absent from offline URL matching.                            | The offline cache recognizes `savedProgress` URLs.                                                                                                            |
| Low      | Settings became awkward in short viewports when expanded.                                | The close/header row stays visible while necessary content scrolling remains available.                                                                       |
| Low      | Initial hydration briefly showed empty results or flashcards.                            | Both views display an explicit loading state.                                                                                                                 |
| Low      | The exam title became a fragment on narrow screens.                                      | Small screens prioritize the question count; the mode remains available in the navigator and accessible label.                                                |

## Design and scope decisions

- Kept the warm palette and moderate border/hover treatment; no further palette replacement.
- Reused existing dialogs, controls, state and browser storage. Added no dependencies,
  accounts, backend services or gamification.
- Kept scrolling when content genuinely exceeds the viewport. Hiding all scrollbars
  would conceal settings at short heights or enlarged text sizes.
- Kept learning aids available in the full practice test. A separate strict assessment
  mode, historical assisted-score tracking and new study analytics are outside this pass.

## Remaining opportunities

- Add an unknown-only flashcard filter or resume the exact card/deck if usage supports it.
- Consider optional single-letter shortcuts and a screen-reader feedback announcement,
  following assistive-technology testing.
- Consider topic/flag filters for long result reviews rather than adding a new dashboard.
- Review the browser-back sentinel approach on physical iOS devices before simplifying it.
- Consider a service-worker update indicator if users encounter stale versions. Automatic
  updates should not interrupt an active test.

## Verification and limits

Validation: 69 unit tests passed; the final full Chromium run passed all 51 browser
tests. Lint, TypeScript checking, production build and diff whitespace checks passed.

Regression coverage exercises saved retake protection, section consent, late expiry,
result identity, cross-tab clearing, quota failure and retry, flashcard synchronization,
compact settings focus, offline save URLs and narrow results geometry. Existing tests
also cover the complete exam journey, exit/resume, light/dark contrast and viewport fit.

Visual checks included the section dialog and results at 320px, single-row navigation
at 320/375/768/1024px, and expanded settings in a short landscape viewport. Browser
automation uses Chromium; this is not physical-device or full screen-reader certification.
The 140 questions and 123 flashcards pass the repository's structural/content checks;
this pass did not independently fact-check every driving rule against current legislation.

Next.js reports an existing workspace-root warning caused by a lockfile outside this
repository. The production build succeeds; no external lockfile was modified.
